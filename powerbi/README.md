# Power BI report

## Fastest way: open the ready-made project (15 minutes)
`pbip/Order_Fulfilment.pbip` is a **Power BI Project**: the data model (tables, relationships, 41 DAX measures, a Discount Cap what-if table, a calendar table) and a 7-page report, saved as text files so GitHub can show them.

1. Install **Power BI Desktop** (free, Microsoft Store). If the .pbip will not open, turn on **File > Options and settings > Options > Preview features > Power BI Project (.pbip) save option** and restart.
2. Open `pbip/Order_Fulfilment.pbip`.
3. **Home > Transform data > Edit parameters** and set **DataFolder** to the full path of this repo's `powerbi/data/` folder, ending with a backslash, e.g. `C:\Users\Ananya\order-fulfilment-plan-vs-actual\powerbi\data\`. Click **Apply changes**, then **Refresh**.
4. **View > Themes > Browse for themes** and pick `plan_vs_actual_theme.json`.
5. Check the numbers on page 1 (164,572 lines, 42.7% on time, 12.0% margin, 94% discount vs profit), then tidy the layout, colours and conditional formatting.
6. **File > Save as** `Order_Fulfilment.pbix`, **File > Export > PDF**, and screenshot each page into `images/`.

This project was generated by `python/build_pbip.py` and has not been opened in Power BI Desktop yet. If a visual shows an error, delete it and rebuild it from the page notes below; the model and measures are the important part.

# Build it yourself: page-by-page guide

Everything needed to build `Order_Fulfilment.pbix` in **Power BI Desktop** (free, Windows) in about 3 to 4 hours. The data is already cleaned and every flag is calculated in SQL, so Power BI only needs the model, the measures and the visuals.

**Design reference:** the interactive dashboard in `docs/index.html` (screenshots in `images/`). Build the Power BI pages to match it.

## What is in this folder
| File | What it is |
|---|---|
| `data/fact_order_lines.csv` | 164,572 order lines (Jan 2015 to Sep 2017) with plan vs actual flags. Exported by `sql/07_powerbi_export.sql` |
| `data/dim_shipping_mode.csv` | Shipping modes with promised days and sort order |
| `data/dim_discount_band.csv` | Discount bands in the right order |
| `data/kpi_targets.csv` | The 6 KPIs, rule (>= or <=) and target |
| `data/bridge_steps.csv` | Steps for the margin-bridge waterfall |
| `data/forecast.csv`, `data/forecast_error.csv` | Forecast results from `python/forecast.py` |
| `measures.dax` | Date table, relationships and all DAX measures |
| `plan_vs_actual_theme.json` | Colour theme matching the dashboard |

## Step 1. Load and model (45 min)
1. **Home > Get data > Text/CSV** and load every file in `data/`. In Power Query check types: dates as Date, money columns as Decimal number, flags (`on_time`, `within_tolerance`, `delivery_breach`, `margin_breach`) as Whole number. **Close & Apply**.
2. **View > Themes > Browse for themes** and pick `plan_vs_actual_theme.json`.
3. **Modeling > New table** and paste the `Date` table from `measures.dax`. Sort `Date[Month]` by `MonthNo`; **Mark as date table**.
4. **Model view**: create the three relationships listed in `measures.dax` (Date, shipping mode, discount band). Sort `bridge_steps[step]`, `dim_shipping_mode[shipping_mode]` and `dim_discount_band[discount_band]` by their `sort_order`.
5. **Modeling > New parameter > Numeric range**: name `Discount Cap`, minimum 0, maximum 0.25, increment 0.01, default 0.10. Tick "Add slicer to this page".
6. Create every measure in `measures.dax` (**Home > New measure**). Format the % measures as Percentage with 1 decimal.

**Check:** a card with each measure should show Order Lines **164,572**, On-time % **42.7%**, Within Tolerance % **76.3%**, Avg Slippage **0.57**, Margin % **12.0%**, Discount **$3.32M**, Profit **$3.53M**, and Cap Saving **$1.02M** at a 10% cap. If they match, the model is right.

## Step 2. Build seven pages (2.5 to 3 hours)
Canvas: 16:9. Put the same four slicers at the top of pages 2 to 4 and 6: **Year** (`Date[Year]`), **Market**, **Shipping mode**, **Customer segment**. Sync them across pages (**View > Sync slicers**). Page titles should state the finding, not the topic.

### Page 1. Project objectives
The first thing a reviewer sees.
- Text box: the business problem ("Orders are promised a delivery date and a price. How often does the business keep those promises, and what does missing them cost?").
- Four cards or text boxes, one per objective, each with its key result:
  1. Plan vs actual with tolerance: 42.7% on time, 23.7% break the 1-day tolerance.
  2. Dashboard and cost-saving case: discounts $3.32M vs profit $3.53M; 10% cap keeps up to $1.02M.
  3. Forecast: orders within 0.9% error, late rate within 1.3%.
  4. One-click monthly report: 6 KPIs checked; Sep 2017 passed 1 of 6.
- Buttons linking to each page (**Insert > Buttons > Navigator > Page navigator**).

### Page 2. Overview
- Cards: Order Lines, On-time %, Within Tolerance %, Avg Slippage, Margin %, Discount vs Profit.
- Line chart: X `Date[Month]`, Y `On-time %`. Analytics pane > Constant line at 0.45 (target).
- Line chart: X `Date[Month]`, Y `Margin %`. Constant line at 0.12.
- 100% stacked bar: Y `dim_shipping_mode[shipping_mode]`, values `On-time %`, `One Day Late %`, `Breach %` (green, amber, red).

### Page 3. Delivery: plan vs actual
- Clustered bar: Y shipping mode, X `Avg Promised Days` and `Avg Actual Days` (grey and red). This is the plan-vs-actual comparison.
- **Matrix with drill-down:** rows `market`, then `region`, then `country`; columns `shipping_mode`; values `Breach %`. Conditional formatting > Background colour (white to red). Turn on the drill arrows.
- Column chart: X `slippage_days` (Don't summarize), Y `Order Lines`.
- Dynamic title: a Card with `Title Delivery`.

### Page 4. Profit and discount case
- **Waterfall (margin bridge):** Category `bridge_steps[step]`, Y `Bridge Value`. Colours: increase blue, decrease red, total green.
- Cards: `Profit on Profitable Lines`, `Loss Amount`, `Loss Lines %`.
- **Discount Cap slicer** (from Step 1.5) with cards `Cap Saving`, `Profit Uplift %`, `Lines Affected %`. Moving the slider recalculates the business case.
- Column chart: X `dim_discount_band[discount_band]`, Y `Margin %`.
- Table: `category`, `Amount Paid`, `Expected Margin %`, `Margin %`, `Margin Gap (pts)`, `Margin Breach %`, `Loss Amount`, `Cap Saving`. Sort by Amount Paid.

### Page 5. Forecast
- Line chart from `forecast` with `series` = "Orders" as a filter: X `month`, Y `actual`, `test_prediction`, `forecast` (blue, amber dashed, green).
- Same chart for `series` = "Late-delivery rate".
- Table from `forecast_error`: model, orders MAPE, late-rate MAPE.
- Text box: "Best models: Holt-Winters for orders (0.9% error) and 3-month average for late rate (1.3%). Forecast for Oct to Dec 2017: about 57.8% late."

### Page 6. Monthly KPI report
- Matrix: rows `kpi_targets[kpi]` (sorted by sort_order), columns `Date[Month]`, values `KPI Status`. Conditional formatting > Font colour or Icons on `KPI Pass` (1 green tick, 0 red cross).
- Table for one month (Month slicer): `kpi`, `KPI Target`, `KPI Actual`, `KPI Status`.
- Card: `KPIs Passed` & " of 6".

### Page 7. Method and data checks
Text boxes copied from the Method tab of the dashboard: definitions, data checks, limitations, source.

## Step 3. Publish to GitHub (20 min)
1. **File > Save as** `powerbi/Order_Fulfilment.pbix`.
2. **File > Export > Export to PDF** as `powerbi/Order_Fulfilment.pdf`.
3. Screenshot each page (Windows + Shift + S) into `images/` as `powerbi_page1_objectives.png` and so on.
4. In the main README, add a **Power BI report** section with the screenshots and a link to the PDF. GitHub cannot run a .pbix file, so the screenshots and the PDF are what people see.
5. Optional: if she has a work or school Microsoft account, **Publish to web** from Power BI Service gives a live link to add to the README.
